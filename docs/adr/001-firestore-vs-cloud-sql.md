# ADR 001: なぜ Cloud SQL ではなく Firestore を採用したか

- ステータス: 採用
- 日付: 2026-09-04

## 状況

UCHI+ は家族数人が使う私的なアプリです。

- データ量: 予定・写真・経費あわせて年間で数千件程度
- 同時アクセス: 多くても 3〜5 人
- 運用者: 家族の 1 人 (専任の DBA はいない)
- 予算: できれば月数百円以内

保存するデータは、
家族 → メンバー / 予定 / アルバム / 写真 / 経費
という **明確な階層** を持ちます。

## 決定

**Cloud Firestore (Native モード)** を採用します。

## 検討した選択肢

### A. Cloud SQL (PostgreSQL / MySQL)

**利点**
- SQL が使える。`GROUP BY category, SUM(amount)` のような集計が一発で書ける
- 外部キー制約でデータの整合性を DB が保証してくれる
- 経験者が多く、情報も多い

**採用しなかった理由**
- **止められない**。Cloud SQL は最小構成 (db-f1-micro) でも
  インスタンスが立ち続けるため、誰も使っていない深夜も課金されます。
  月あたり数千円になり、「家族数人のアプリ」としては見合いません。
- **接続管理が要る**。Cloud Run はリクエストごとにインスタンスが増減するため、
  コネクションプールや Cloud SQL Auth Proxy の設定が必要になります。
- **アクセス制御を全部自分で書く必要がある**。
  Firestore なら Security Rules で「DB 側の防御」を持てますが、
  SQL ではアプリのコードが唯一の防御線になります。
  バグが即データ漏洩に直結します。

### B. Cloud Firestore ← 採用

**利点**
- **使わなければほぼ無料**。従量課金で、読み書きの回数と保存量だけで決まります。
  家族利用なら無料枠 (1 日 5 万 read / 2 万 write) にほぼ収まります。
- **Security Rules がある**。アプリのバグと独立した防御層をデータベース側に置けます。
  本プロジェクトで最も重視した点です ([ADR 005](./005-security.md))。
- **階層構造と相性が良い**。
  `families/{familyId}/expenses/{expenseId}` のように家族単位でデータが自然に分かれ、
  `match /families/{familyId}/{document=**}` で家族ごとにまとめて守れます。
- **サーバーレスとの相性**。コネクションプール不要、HTTP ベース。
- Firebase Authentication との統合 (`request.auth.uid`) が最初から使えます。

**諦めたこと**
- **JOIN が無い**。「この経費を申請したのは誰か」は、
  メンバー一覧を別途取得してアプリ側で突き合わせています。
- **集計が弱い**。SUM / GROUP BY がありません
  ([ADR 006](./006-aggregation.md) で対処方法を決めています)。
- **2 つのフィールドに同時に範囲条件を付けられない**。
  カレンダーの「期間の重なり」判定は、
  片側だけ範囲クエリにしてアプリ側で絞り込んでいます
  (`src/lib/data/events.ts`)。
- **クエリの自由度が低い**。あとから「やっぱりこの条件で検索したい」となると、
  複合インデックスの追加やデータ構造の変更が必要になります。

### C. BigQuery / Cloud Spanner

規模が桁違いに大きい用途向けで、家族アプリには過剰です。
Spanner は最小構成でも月数万円かかります。

## 結果

- 月額をほぼゼロに抑えられます
- Security Rules という「アプリのバグとは独立した防御層」が手に入りました
- 集計と JOIN は自分で書く必要があり、その分のコードが
  `src/lib/data/expenses.ts` に集まっています

## 見直す条件

以下のいずれかに当てはまったら Cloud SQL / AlloyDB を再検討します。

- 経費が月 1,000 件を超え、都度集計の read が無視できなくなった
- 「昨年の食費を月別に並べて前年比を出す」のような分析要求が増えた
- 家族以外 (親戚や友人グループ) にも広げ、データ量が桁違いになった
